## 1. 目标与非目标

目标：

- 保留原生候选的即时可用性；本地模型加载、推理、故障均不得阻塞普通输入。
- 根据上下文重排已有候选，并持续学习个人的条件选词偏好和词间搭配。
- 增加领域适应：近期输入领域术语后，相关候选获得有上限、可衰减的加权，而不是永久改写整个领域的词频。
- 保留现有云端生成式候补作为独立、显式触发的能力；本地不可用时不自动回退云端。

第一阶段不做：完整 BiLing 前端移植、第二套基础词库与解码器、逐键模型训练、LoRA 个性化、任意整句错拼修复，以及停键后的自动神经重排刷新。

可行性判断：本地打分与有限持久学习可行；整域升权需要补充设计；完整 BiLing 式交互需要额外的候选生成与前端桥接工作。

## 2. 建议架构

```text
Fcitx5 / Rime
│
├─ 原生词库、script_translator、userdb
│    └─ 基础候选始终立即可用
│
├─ 现有 ai.trigger / ai.suggest
│    ├─ 候选快照、范围、身份
│    ├─ 非阻塞收包
│    └─ 按有效结果重排原始候选
│
├─ UDS → 本地 ranker 服务
│          ├─ 上下文、学习状态、请求调度
│          ├─ SQLite 聚合统计
│          └─ 隔离的 llama.cpp 打分 worker
│                └─ Qwen3-0.6B-Base GGUF
│
└─ 现有云端 candidate-daemon
     └─ 继续保持独立、显式触发
```

图中的快照与重排是对现有 Lua 模块的拟议扩展，不是其当前能力。“立即可用”指不增加等待模型的前置条件，不表示原生解码耗时为零。Qwen3-0.6B-Base 是起始评估模型，不是已冻结的依赖或性能承诺。

### 2.1 职责分工

| 层 | 建议职责 | 不承担 |
| --- | --- | --- |
| Rime 原生引擎 | 词库召回、组词、基础排序、userdb 学习 | 等待模型结果 |
| `ai.trigger` / `ai.suggest` / `ai.glue` | 有界快照、身份与版本校验、非阻塞通信、重排原始候选 | 神经推理、SQLite 读写、持久学习计算 |
| 本地 ranker 服务 | 上下文管理、分组、融合、学习状态、调度与降级 | 云端调用、直接操作运行中的 userdb |
| 打分 worker | 批量候选打分、上下文 KV 缓存、资源与任务生命周期 | 自由生成候选文本、输入法界面操作 |
| 云端 candidate-daemon | 保持现有生成式候补通路 | 接收本地学习库、充当本地故障的自动后备 |

建议 Python 负责 UDS、调度与 SQLite，C/C++ worker 适配 BiLing 的打分核心。模型在隔离进程中运行，不加载进 fcitx5；打分核心失败时，原生候选仍可使用。

服务与构建产物位于 `rime/` 部署单元之外，模型与学习状态不入 Git。模型准备、依赖检查和服务运维仍通过根目录 `./run.sh` 编排；新增命令及目录在实施时确定。可选原生组件会增加构建与版本维护成本，但不引入 YAML → Rime 词库的转换层。

## 3. Rime 集成的必要契约

### 3.1 候选可比性与原始对象

不能假设菜单前 N 项就是 N 个完整句子的不同写法。已核查的 `librime@1.10.0` 中，`script_translator.cc` 的自动组句路径使用单个 `sentence_`，菜单还可能包含覆盖部分输入的词条。重排前必须先确认候选覆盖率与可比性。

- 快照携带候选 ID、文本、输入起止范围、来源、原始排名及可用的质量信息；固定短语等保护项需可识别。
- 第一版仅在相同输入覆盖范围、可比较的候选组内重排，不将局部词与整句混排。
- 返回 ID 对应的分数或顺序，重排时复用原始候选对象；不把候选文本重新包装为普通 `Candidate("ai", ...)`。
- 保留未参与重排的候选、固定短语的保护边界和原生局部选词行为。
- 快照应来自未被本轮模型结果污染的基础候选，避免重复加分和自我反馈。

`librime` 的学习路径会追溯原始 `Phrase`，因此对象身份不仅关系显示，也关系 userdb 学习与删除行为。正确答案未被召回时，重排无法补救；增加模型规模不能替代候选生成。

### 3.2 请求身份与过期结果

请求及缓存不能只按输入拼音索引。建议绑定：

```text
会话身份 + 组词代次 + 上下文版本 + 当前输入
         + 已选前缀 + 输入范围 + 候选快照版本
```

候选 ID 仅在所属快照内有效。输入、已选前缀、上下文或候选集合变化后，旧结果必须失效；上屏、取消、切换输入上下文和重新连接均需定义失效边界。显示前重新校验身份，不把“结果已经计算完成”视为“仍然适用”。

现有云端协议不直接改作本地重排协议。新协议的版本、字段和兼容行为在实施时形成组件说明，本文不提前冻结线协议。

### 3.3 显式触发与自动刷新分开

第一版采用现有 Tab 式显式请求交互：允许在触发路径处理候选快照，普通输入不等待模型。**本地与云端的具体触发键或模式路由尚待评审**；不能默认一次 Tab 同时请求两路，也不能未经决策改变现有云端入口。

完整自动版另行实现。当前 Lua 通路不能在用户停键后自行消费回包并完成界面刷新；“下一键再收包”也不保证有用，因为下一字母可能已使请求失效。

要实现停键后的自动原位重排，需要与 `fcitx5-rime` 协作的原生桥接，同时完成引擎候选重算和前端刷新，不能仅刷新界面。必须保证：

- 引擎与界面的候选顺序、选择索引保持一致。
- 用户已经导航、翻页或开始选择后，迟到结果不能移动其正在选择的候选。
- 旧上下文的回包不能作用于新输入框；不采用后台线程直接操作 Rime/Lua 的方式。

### 3.4 上下文能力分级

近期上屏记录不等于光标前的真实文档。它不能可靠反映光标移动、删除、粘贴或输入框切换。

第一版只承诺有限的近期输入上下文；拿不到可靠输入框身份时，不能宣称已经实现跨应用隔离，应采用保守清空、手动重置或禁用上下文的降级方式。

后续通过 Fcitx5 原生接口接入 surrounding text、焦点与应用信息；按应用实际支持程度降级，不能把不可获取的正文补猜成上下文。输入内容与上下文的收集需先经过隐私判定。

## 4. 持续学习与领域适应

保留 Rime 的基础词频学习；新增模型优先学习条件增量，避免两套系统对相同使用次数重复加权。

| 学习对象 | 建议机制 | 边界 |
| --- | --- | --- |
| 条件选词偏好 | 根据确认选择更新有界统计；区分近期与长期证据 | 未选候选不自动视为错误，未展示候选不能作负反馈 |
| 个人词间搭配 | 保存确认文本中可信的词对统计，与基础排序保守融合 | 没有可靠分词或对齐信息时不强行学习 |
| 当前领域与长期偏好 | 领域状态采用不同衰减尺度，对相关候选增加有上限的分数 | 不永久整体升高词库词频，切换话题后应能恢复 |
| 个人错拼 | 后续建立原始按键到确认结果的可靠配对与修复候选召回 | 不把所有退格当成错误标签，第一版不承诺完整纠错 |

领域适应可以先从现有 [嵌入式领域词库](../../rime/cn_dicts/embedded.dict.yaml)提取种子，验证“示波器、GPIO → 电平、功耗”的跨词加权。必须用未被直接学习过的同领域词测试泛化，并检查切回日常话题后的恢复，不能用重复选过同一个词来证明整域升权。

上述显式领域状态是本项目需要补充的设计，不是 BiLing 已提供的完整模块。其即时持久学习主要是选词与搭配统计；模型利用上下文的语义判断与长期领域画像是两件事。

### 4.1 持久化与隐私

- SQLite 仅保存必要的聚合统计，不照搬原始事件表，不以更换文件格式的方式绕过 D-1。
- 用户派生状态不入 Git、不自动上云；应有容量上限、清除与禁用学习的入口。
- 文件权限限制不等于加密。是否加密、密钥托管及删除语义需单独评审，不能直接照搬 Keychain，也不复用云端 API key。
- 敏感输入场景禁止学习；没有可靠的隐私判定信号时应保守关闭相关收集能力。
- 日志默认只记录耗时、计数与错误类别，不记录输入、上下文、候选原文；实施时核查并处理现有 daemon 的原文日志路径。
- 不直接读写运行中的 `rime/pinyin.userdb/`；词条晋升仍遵循 [词库 SOP](../design/lexicon-sop.md)。

### 4.2 LoRA 不作为首版依赖

已核查的 BiLing `TrainingDataExporter.swift` 主要导出被选择的文本，而非完整的“拼音—上下文—纠错”样本。它可参考用于词汇分布适应，但不能直接视为个人拼音纠错训练方案。是否引入 LoRA，应由独立留出集上的候选收益决定，而不是由训练 loss 下降决定。

## 5. 打分、性能与降级

BiLing 的打分核心对已有候选做条件打分，不等同于调用聊天生成接口。保留批量计算与上下文缓存的思路，但不直接复用其融合权重和门控 JSON：Rime 的 `quality` 与 BiLing 的对数概率不是同一尺度，需在本项目候选上重新校准。

以下是起始验证目标，不是已实测结果：

| 项目 | 目标或约束 |
| --- | --- |
| 普通输入 | 不等待模型、数据库或服务恢复 |
| Lua 热路径 | 保持 D-19：≤ 0.1ms/键，且非阻塞 |
| 预热后本地打分 | 8–16 个可比候选、上下文上限固定的条件下，先验证 p95 ≤ 80ms；报告实际测试条件 |
| 冷启动与故障 | 独立报告耗时；增强未就绪时保留原生候选，不隐式改走云端 |
| 队列 | 有界调度，优先最新有效请求；丢弃过期任务，避免逐键积压 |
| 候选稳定性 | 导航后不被迟到重排干扰，无跨会话回包污染 |

性能验证应包括 Lua、候选快照、IPC、模型、结果应用以及端到端 p95/p99。提前拉取惰性候选流可能增加底层解码成本，不能只测 Lua 或模型服务。CPU 与 GPU 都做对照，不能用上游另一平台的延迟代替本项目实测。

同一 llama.cpp 上下文不并发执行打分；调度与 worker 隔离设计需保证缓存一致性。本次核查的 llama.cpp 头文件仍将 abort callback 标为 CPU 执行支持，因此不能把 GPU 中途立即取消当作可靠前提，应依赖有界批次、代次校验和过期结果丢弃。

| 上游 | 核查对象与用途 |

| BiLing，同一提交 | `Sources/BackboneEngine/UserDictionary.swift`、`ConfidenceGate.swift`、`TrainingDataExporter.swift`：学习、门控和训练数据边界 |
| BiLing，同一提交 | `Sources/InputSessionCore/CandidateStabilityController.swift`、`CompositionContext.swift`：候选稳定性与上下文身份 |

| fcitx5-rime `5.1.4` | `src/rimestate.cpp`：引擎结果与前端刷新衔接 |
| llama.cpp `6a1a922d269908a29cbd4b49c27e6a8e7fd10fae` | `include/llama.h`：C 接口及取消能力的核查基线 |

评估期间在仓库外替换 Apple 向量运算与计时接口、适配模型加载参数后，C 打分核心通过 Linux C11 的 `-Wall -Wextra -Werror -fsyntax-only` 检查。该探针**未链接、未加载模型、未验证推理正确性或性能**，不能作为可部署证明；标量替代也不是生产性能实现。

实际复用时固定依赖版本，保留适用的许可证、版权说明与 NOTICE，并分别核对代码、模型和数据的许可。无需移植 AppKit、IMKit、XPC 或整套 Swift 工程。

## 7. 分阶段验证与推进条件

| 阶段 | 范围 | 推进条件 |
| --- | --- | --- |
| P0：离线验证 | C 核心链接与实际打分；Rime 候选覆盖率、范围分组；CPU/GPU 对照 | 正确候选有足够覆盖；重排有收益且延迟可接受 |
| P1：显式本地重排 | 经评审的触发入口、原始候选重排、失效校验、有限持久学习、故障降级 | 原生学习与局部选词不回归；重启后学习状态一致；无隐式上云 |
| P2：轻量自动领域适应 | 后台更新领域状态，输入侧使用有界快照 | 通过 D-19 预算，未学过的同领域词有收益，跨话题负迁移可控 |
| P3：自动神经重排 | 原生 Fcitx5-Rime 桥接、真实文本上下文、停键刷新、稳定性控制 | 引擎与显示顺序一致；焦点切换与迟到回包安全 |
| 后续：整句与纠错 | 按覆盖率结果补充受拼音约束的候选生成与修复 | 有独立效果证据，再决定是否引入训练通路 |

测试覆盖通用文本、嵌入式领域、混输、局部选词、话题切换与错拼；区分候选缺失和排序错误。学习评估按时间顺序先预测后更新，避免测试答案提前进入学习状态。记录首选准确率、候选覆盖率、误纠错率、通用输入回归及尾延迟。

配置集成后通过 `./run.sh verify` 做隔离 staging 构建，并进行真机逐键抽查；模型效果与性能需要另行验证，不能由 staging 构建通过替代。一次性探针、候选快照和回放中间产物不入库。

优先推进 P0 → P1。若正确答案经常未被召回，先解决候选生成，不优先投入自动刷新或扩大模型。

## 8. 实施前待评审事项

决策编号正文见 [architecture.md §2](../design/architecture.md)。本文只列需要协调的边界：

| 决策 / 事项 | 需要明确的内容 |
| --- | --- |
| D-1 / D-3 | 允许的聚合学习状态及其生命周期；不另建输入流水或手工置顶、隐藏、降频规则层 |
| D-5 / 部署单元 | 可选原生服务的构建与依赖归属；保持 `rime/` 原生格式与独立部署 |
| D-17 / D-18 | 本地重排与云端生成的职责、结果展示及候选顺序契约 |
| D-19 | `ai.suggest` 的有界重排职责及测量口径；性能与非阻塞红线不放宽 |
| D-21 | 本地自动增强是否获准；云端始终显式触发，不把“本地”当成自动豁免 |
| 入口与隐私 | 本地/云端键位或模式路由；会话身份、敏感字段识别、学习开关与清空入口 |
| 参数与依赖 | 模型与 llama.cpp 固定版本；候选数、上下文上限、超时与门控依据实测确定 |

落档不等于上述事项已经拍板，也不授权安装模型、切换输入方案或改变现有数据外发边界。
