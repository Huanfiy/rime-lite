## 1. P0 离线测评（2026-10-12）

### 1.1 口径

- **语料**：仓库文档 5367 条、中新网 2026-10-12 新闻 4693 条，都晚于模型训练截止。
- **切分与上文**：jieba 逐词切分，pypinyin 全拼。上文取文档前文 80–160 字，不是上屏历史。
- **候选**：staging 加当日 userdb 快照，Rime 基线即当时的真实排序。
- **样本**：只计 Rime 已召回正确词、且同字数候选 ≥ 2 的样本。
- **调参**：融合权重在偶数 id 半集上选定，在奇数 id 半集上报告。

### 1.2 首选正确率

| 集合 | Rime | 仅 LM（无上文） | 仅 LM（有上文） | 融合 | 修正 / 误改 |
| --- | --- | --- | --- | --- | --- |
| 文档 | 83.9% | 53.9% | 89.7% | 90.8%（W=1） | +263 / −79 |
| 新闻 | 78.1% | 52.4% | 95.3% | 96.1%（W=2） | +462 / −40 |

- **收益全部来自上文**。无上文时 LM 比 Rime 低约 30 个百分点，所以名次先验必须参与融合。
- **单字词提升最大**：文档 71% → 85%，新闻 71% → 91%。
- **误改约占 Rime 原本正确样本的 2–3.5%**，主要是「的 / 得 / 地」这类要看下文才能判断的词。
- **未测缺口**：样本是逐词输入，属于 Rime 最吃亏的情形。整句或多词输入时 Rime 组句已利用句内上下文，收益可能缩小。

### 1.3 前缀（「系统提示词」）

base 模型的前缀只是拼在上文前的一段文本。

- **无上文时，前缀能推动偏好**：60 个嵌入式术语中，术语排首位的数量从 32 升到 41（嵌入式标题前缀）。Rime 现有排序本身是 50。
- **有上文时，前缀不起作用**：四种前缀的结果差异 ≤ 0.5 个百分点，在标准误以内，领域匹配与错配没有区别。
- 结论：不以前缀控制偏好，可调的是 W、MARGIN 等模型外参数。

### 1.4 延迟

| 请求 | p50 | p95 | p99 |
| --- | --- | --- | --- |
| 增量（上文前缀复用） | 38ms | 67ms | 84ms |
| 整段上文重算 | 140ms | 205ms | 207ms |

llama-bench 测得预填充约 400 tok/s；增加线程或绑核均无改善。

## 2. 停顿重排真机试用（2026-10-12 13:58 – 10-15 09:56）

参数为 W=1、MARGIN=0、停顿 200ms。上文为本会话上屏历史（PoC 版，逻辑与 D-30 现行版一致）。

| 项 | 数值 |
| --- | --- |
| 发出请求 | 约 2274 次 |
| 期间有真实按键、被作废 | 约 470 次（≈ 21%） |
| 完成打分 | 1802 次；其中改首选 484 次（26.9%），实际应用 469 次 |
| 插件异常（超时 / 服务不可用 / 坏包） | 0 次 |
| 打分耗时 p50 / p90 / p95 / p99 / max | 46 / 94 / 106 / 121 / 172ms |
| 停顿到生效 p50 / p90 / p95 / p99 / max | 50 / 93 / 105 / 128 / 250ms |
| 上文重算（`head_dec` ≥ 20 token） | 6 次，p50 141ms，max 172ms |

- **候选数分布**：16 个的请求占 1251/1802。2 个候选的请求有 104 次，其中改首选 10 次，对应已知问题「强短语被推翻」。
- **普通按键开销**（staging 对照）：每键增加 ≈ 2–4µs。
- **主线程注入阻塞**：快照 41–162µs，应用 22–82µs。
- **用户反馈**：试用 3 天后判断效果良好，转正为 D-30。日志不记原文，因此无法统计改动的正确率。
